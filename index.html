Discord message ingestion

At-least-once, out of order, still correct.

A bot backfills a channel’s history, then keeps ingesting live events into SQLite. Delivery is neither ordered nor exactly-once, so the storage layer assumes the worst.

Stale writes can’t win.

Every write is an upsert on message ID with a recency guard. A copy pulled during backfill cannot overwrite an edit that arrived live a moment earlier.

Early deletes aren’t lost.

Deletions land in a tombstone table, so a delete that arrives before its insert still takes effect. A forward-only cursor and a background reconcile loop close the gaps that disconnects leave behind.
